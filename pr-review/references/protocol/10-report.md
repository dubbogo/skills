## 10. 收尾对账

**本节只回复当前用户聊天，不执行任何 GitHub 写入。** 文中的“收尾报告”“对账”“总结”均指当前聊天的本地报告，不是 PR Conversation、GitHub review body 或新的 GitHub 评论。已发布的问题不再向 PR 重复汇总；被 `R02` 跳过的 PR 只说明原因，不展开本节模板。

先列 Findings，按严重性排序，每条给出位置、触发条件、影响、证据和修复方向。没有 Findings 时明确说明，同时保留验证边界。不要求为无关项目输出空模板。

随后简要对账：

```text
代码审查：[有阻断问题 / 未发现阻断问题 / 审查未完成]；[理由或未覆盖范围]
验证证据：[充分 / 具体缺口]；[命令或 CI 链接、实际测试 SHA、平台、结果]
GitHub 状态：[当前状态]；[规则依据、必需检查及审批情况]
快照：[owner/repo、repository id、PR、目标分支、Base/Head、Diff 基准及适用的 merge-base OID、适用的 merge result、最终复检]
Diff：[声明文件数 / 已获取唯一文件数]；[获取完整性、实际审读范围与未覆盖路径]
评论：[发现数 / 新发数 / 已有线程覆盖数 / 未发布数及原因]；[链接]
证据目录：[本轮实际绝对路径]；[其他残留产物或运行资源，如有]
Review 经验复利：[记录位置及要点 / 无新增可复用经验]
```

**结论口径**：收尾报告与给作者的结论必须逐条标明是「实测」（附命令、exact Head、平台与结果）还是「源码级判断」（附判断依据的调用链），不得用"经验证""跑过了"这类不区分证据来源的措辞。无法实测的结论写明阻塞原因与未覆盖范围；给作者的复现说明必须带具体命令与配置来源，不能只写"CI 会挂"。本地门禁与 CI 结论的口径差异按 `R05`、`R15` 标注；写"已有防御 / 已有覆盖"之前，先确认校验两侧不是同一信息源。

各字段的阈值取值约定：

- "审查未完成"必须同时给出未覆盖的路径清单或维度，不允许只写结论。
- 未覆盖路径超过 20 条时，按模块聚合，并说明聚合规则。
- 必要检查未执行时写"不适用 / 已复用 CI / 环境阻塞"，并说明对 Merge 结论的影响，不写成"不需要"。

原始 API 响应、命令输出、退出码和详细清单保存在证据目录，聊天中只呈现支撑结论的内容。只列实际使用的平台路径，不逐项列出缓存与依赖文件。不要求统计工具调用次数；用户需要时由执行记录自动统计，无法准确统计则明确说明，不估算。
