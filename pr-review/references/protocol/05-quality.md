## 5. 核心质量矩阵

对适用项逐项核对，不为"凑数量"生成评论：

1. **需求闭环**：正常、边界、异常、回滚路径。条件表达式与空值处理是语义漂移的高发点：核对 `null` / 空串 / `0` / `false` / 未设置是否被区分，以及同一判定在不同入口是否给出相同结论。
2. **接口与外部依赖**：API、协议、配置、数据格式和调用方是否兼容；依赖版本、超时、重试、退避、熔断和降级策略是否安全且有界。依赖、SDK 或工具升级还需核对官方兼容矩阵、最低运行时/服务端/工具链、端口与权限、生命周期接口和下游最小消费者。删除或简化既有重试、超时、退避、熔断、降级或兜底逻辑时，核对 git 历史与关联 Issue，确认该保护不是历史事故后添加的。
3. **测试强度**：成功、失败、边界和回归测试。
4. **数据安全**：输入、权限、敏感数据和序列化。
5. **并发安全**：竞态、死锁、锁粒度、取消和退出。
6. **资源管理**：文件、连接、内存、事务、线程和 Goroutine；所有权必须覆盖成功、失败、取消、超时和重启路径，快照或缓存还要检查嵌套可变对象是否真正隔离。
7. **性能复杂度**：O(n²)、无界增长、多余复制和高频分配。典型线上量级风险：循环内重复查询或远程调用（N+1）、无分页全量加载、线程池/连接池参数与预期负载不匹配；本地小数据量通过不能证明线上量级成立。主张改善必须附测量或复杂度推导（§4 量化要求）。
8. **日志可观测性**：错误上下文、敏感信息和诊断能力。
9. **代码瘦身**：死代码、残留 TODO、无效兼容层和重复实现。
10. **架构一致性**：分层、抽象、扩展点和依赖方向；新增 import 是否形成循环依赖或反转依赖方向。按语言和依赖类型判断：Go 包级 import cycle 会阻止构建；Rust 模块/类型相互引用与 Java 类相互引用不必然是编译错误，应具体核对类型递归、初始化顺序、静态初始化和运行时装载行为；Python 循环 import 可能暴露部分初始化模块。不得把所有循环依赖一概描述为编译失败或运行时偶发异常。

### 5.1 Import / Header 顺序

- **C++**：关联头文件 → C 库 → C++ 标准库 → 第三方库 → 项目内部库。
- **Go / Python**：标准库 → 第三方库 → 项目内部包或本地模块。
- **Rust**：`std` → 外部 crates → `crate::` / `self::` / `super::`。
- **Java**：`java.*` → `javax.*` → 第三方库 → 项目内部包。

各组之间按项目格式化工具或本地规范留空行。若项目规则另有规定，以项目规则为准。Import/Header 顺序仅在项目格式化工具、Lint 或明确规范会强制失败，或顺序确实影响语言解析、名称解析或运行语义时，才作为 Finding；纯审美偏好不得上报。

### 5.2 语言禁止项与重点检查

- **C++**：禁止所有权不明的裸指针、裸 `new/delete`、未初始化成员、无含义魔数和生产路径使用 `std::cout/printf` 代替工程 Logger；资源必须符合 RAII。
- **Go**：禁止忽略 `error`、无 context/cancel 或 channel 退出机制的 Goroutine、不受控全局变量和生产路径使用 `fmt.Printf` 代替工程 Logger；检查 defer 成本和 channel 关闭责任。
- **Rust**：禁止外部输入可触发的生产路径 `unwrap/expect`；`unsafe` 必须有 `SAFETY` 依据；检查锁顺序和粒度、无意义 clone、所有权、生命周期及错误传播。测试代码按项目 lint 规则处理，不机械判 P1。
- **Java**：禁止吞异常；检查 `ThreadLocal.remove()`、Spring 同类调用导致的事务失效、资源关闭、`serialVersionUID` 和 Stream 中的复杂 I/O 或副作用。
- **Python**：禁止可变默认参数；核心逻辑应有类型标注；外部输入校验类型、长度和范围；检查异常吞噬、GIL 场景、过度嵌套推导式和无意义 f-string。
