# 第一版结构与转换决策

目标是把已经确认的方法变成可发现、可独立分发、按需读取的技能，保留真实授权与证据边界。第一版实现三个入口，不创建架构师总控框架。

| 技能 | 入口保留 | 按需资料 |
|---|---|---|
| task-issue | 分析者 → Task Issue → coding agent 的交接、批准与执行模式 | 输入、规划、契约、编码、独立验证、检查点、完整 Issue 模板 |
| py2rust | 任意 Python 项目的范围核实、单元循环导航、真实 Rust 与安装验收 | 现状核实、工具所有权、差分、桥接、门禁、语义、状态和报告；PowerContext 仅作为可选案例 |
| pr-review | 状态门禁、风险与证据、评论和收尾边界 | 保留 §0–§13 的协议分章、10 个 owner/repo 规则索引、诊断经验 |

## 包内独立性

每个包自带完整 Apache-2.0 `LICENSE`、`NOTICE`、相对路径参考资料与可选宿主元数据。安装单个包不要求安装另外两个。Rust 包附任务契约摘要；原文提及的 `issue-harness.md`、`review.md` 是方法来源或任务明确选择的协议，不是失效的本机路径。

`agents/openai.yaml` 提供名称、短描述、显式调用例子，允许正常自动发现。它不是 agent 编排配置，不自动启动子 agent，也不扩大 GitHub、Git 或部署权限。需要持续独立验证时，任务仍须满足真实宿主能力和获批模式。

## 分层和时效

通用 review 协议保留稳定 R 编号、§章节和冲突次序。项目资料按精确 owner/repo 匹配；工程化 PR review 包中的 PowerContext 资料仍按项目规则加载，py2rust 包中的 PowerContext 路径只作为可选案例，不构成其他项目的默认约束。诊断经验按原顶级章节分组索引；首次赋予 EXP 导航 ID，后续新增不重排。

导入不宣称重新验证历史命令、审批数、CI、平台或 PR。资料头部说明适用性，时效性条目按原验证日期与范围复核。上游含冲突历史时，以选定协议为准；本次明确退役“回复会自动恢复 unresolved”“同根因残留另开线程”及未经授权 Resolve 的相反要求。

导入当前工作区，而非假装所有内容都已提交；来源清单同时保存基线 commit、基线内容摘要、实际工作区字节摘要和是否不同。个人机器路径示例参数化；参考文档中的目标仓库路径、符号、SHA 和历史日期保留作为调查证据。

## 维护边界

本仓库是这三个包的新维护源。原 `arch-practice` 工作台不改动，也没有自动同步器；未来上游修订需显式评估并更新来源记录。本机已有旧技能未被覆盖或卸载。使用者选择本包协议时不叠加旧技能的冲突评论通道、分级或自动 Resolve。

第一版不实现自动安装、联网 Issue 发布器、PR 评论发布器或 agent 调度运行时。已有宿主负责执行，技能负责流程和判据。结构校验不证明流程遵守；离线独立评估与真实任务验收分开报告，见[验证记录](validation.md)。
