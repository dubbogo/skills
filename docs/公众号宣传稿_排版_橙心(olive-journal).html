EDITOR'S NOTE 为什么整理这套技能

写需求、拆任务、迁移性能热点、审查 PR，这些工作都能让 Agent 帮忙做。但真正费劲的通常不是让它多写几行，而是把范围、权限、证据和验收讲清楚。

我们把架构实践中反复用到的流程整理成了三个可独立安装的 Agent Skills：task-issue-harness、py2rust 和 pr-review，按任务角色、阶段和风险读取参考资料。

01

PART

 

三个技能，各管一段工程工作

THREE ENTRYPOINTS

task-issue-harness 面向需求分析和编码交接。一个 Agent 核实需求、查看代码并形成 Task Issue；另一个 coding agent 按获批契约实现。持续双 Agent 模式下，独立验证者需要实际读取开工快照并反馈 CONTINUE；如果拿不到真实快照，就不能把验证报告写成 PASS。宿主能力不支持持续独立验证时，流程会如实报告能力缺口，也提供契约批准的 FINAL_INDEPENDENT_REVIEW 与 SELF_CHECK_ONLY 模式。

py2rust 用于评估和实施任意 Python 项目的 Rust 优化，也覆盖完整的 Python → Rust 迁移，两者完成标准不同。它按可独立验收的单元推进，守住三类证据：保持断言强度的行为测试、固定 Python oracle 的无损差分、真实入口加载本次构建的身份与后端证据。干净环境安装 wheel 后还要从公开入口再验一次。性能必须计入桥接、转换与分配成本。Python fallback 全绿不等于 Rust 路径验收通过。

pr-review 用于 PR 初审、更新复审和合并条件判断。它按当前仓库身份和 Base/Head 快照核查变更，区分 PR 新增问题与基线问题。收尾时把代码审查、验证证据和 GitHub 合并条件分三组给结论；CI 关联的 SHA 与实际 checkout 的 SHA 分别记录，源码级判断和实测也要逐条标明来源。MERGEABLE 或绿色 CI 本身都不替代完整的合并判断。

重点

三类证据缺一不可；独立验证者没有真实快照，就不能把自述当成 PASS。

PART

 

为什么入口短，资料却不少

LOAD BY ROLE AND RISK

每个 SKILL.md 都是简短入口，具体规则放在 references/ 里按需加载。pr-review 的参考目录包含 40 份 Markdown、8600 余行，入口 SKILL.md 仅 49 行；项目索引覆盖 10 个 owner/repo。任务只读取相关阶段和目标仓库的规则，旧项目经验也会保留适用范围和验证日期，不会自动变成所有项目的门禁。

PART

 

安装一个技能

START FROM A CLEAN CLONE

git clone https://github.com/dubbogo/skills.git && cd skills

macOS / Linux

skill_name=task-issue-harness

skill_root=\"$HOME/.agents/skills\"

mkdir -p \"$skill_root\"

 

if [ -e \"$skill_root/$skill_name\" ]; then

echo \"Already installed: $skill_root/$skill_name\" >&2

exit 1

fi

 

cp -R \"./$skill_name\" \"$skill_root/$skill_name\"

Windows PowerShell

$skillName = 'task-issue-harness'

$skillRoot = Join-Path $env:USERPROFILE '.agents\skills'

$destination = Join-Path $skillRoot $skillName

 

if (Test-Path -LiteralPath $destination) {

throw \"Already installed: $destination\"

}

 

New-Item -ItemType Directory -Force -Path $skillRoot | Out-Null

Copy-Item -LiteralPath (Join-Path (Get-Location) $skillName) `

-Destination $destination -Recurse

调用示例

使用 $task-issue-harness 核实需求，只给我 Task Issue 草稿。
Use $py2rust to assess a Python hot path; do not implement yet。
使用 $pr-review 审查这个 PR，仅本地报告，不发评论。

04

PART

 

校验做了什么，没做什么

CHECK THE PACKAGE, STATE THE LIMITS

使用技能本身不需要安装 Python；Python 3.11 及以上只用于从源码运行仓库的校验、测试和打包。仓库配置了 Linux、Windows 与 Python 3.11、3.14 的四组合 CI，当前 main 上四组合均通过。每个组合运行相同的离线校验、测试和打包门禁；分发包作为 CI 产物上传并保留七天。

scripts/validate.py 离线检查包结构、元数据、许可证和文档链接等内容；scripts/package.py 负责生成 zip 并解压复验分发文件，测试再核对生成的 SHA-256 清单。这些门禁能发现包结构和文档维护中的一类错误，但不执行技能工作流、不核验远端链接、不证明某个 Agent 一定遵守流程。离线场景测试也不等于真实宿主安装、真实双 Agent 协作或外部系统写入验收。

边界

把边界说清楚，比把校验结果说得过满更重要。
