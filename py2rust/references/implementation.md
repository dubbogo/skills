## 5. 单元实施循环

1. **固定参考与契约**：读取实现及相关测试，列出输入、输出、异常、状态和副作用；记录参考提交、相关源码哈希及依赖。
2. **跑相关基线**：确认测试实际导入本 checkout。保留命令、退出码、结果与跳过原因；只为明确风险增加检查。
3. **生成最小桥接骨架**：若选定的迁移工具需要 `record`、`bridge` 或配置骨架，先按其实际版本建立最小骨架。分析器粒度过大或 API 不受支持时，明确提出小型适配边界；不要用 `--force` 绕过尚未理解的阻塞。
4. **录制 Python 参考行为**：输入来自现有测试、§8 的相关边界和经授权脱敏的实际样本。可使用 `record --from-tests`，但先确认当前工具对该导出形式的捕获能力，核查捕获清单，不能把测试执行数当作录制覆盖数。非确定性或副作用依赖按“录制一次、双端回放”处理：按 [baseline.md](baseline.md) §1 捕获依赖边界两侧的可比较数据（请求/参数、输入输出、解析结果），两侧消费同一捕获物；回放后仍比较调用参数、解析路径与副作用；被计次动作只由一侧真实执行，并断言非执行侧未真实执行。
5. **验证比较器与关键验收的检错能力**：在隔离副本中用代表性的错误返回、错误类型或顺序变化确认差分确实会失败；用缺失扩展或错误构建确认“强制 Rust”不能静默回退。负控必须由测试断言捕获目标结果差异或预期的后端拒绝，不能把与目标无关的缺 API、导入失败或环境错误当作反证。已有适用的失败基线可复用，不要求所有普通测试都做变异；记录临时变更与恢复后的身份，不污染参考端或交付快照。记录格式不能丢失类型、精度或特殊值。
6. **实现 Rust**：按任务中记录的 D1 决策选择人工移植或转译器主线；转译器仅在隔离试验或具体单元已选定接入时使用，只修改该单元和必要桥接。使用工具生成工程时按其实际约定编写源文件，签名变化后按需刷新并检查 diff，重新验证定制的字符串、数值与错误适配器。保留可追溯的 Python 参考，避免形成两套长期各自演化的域规则。
7. **构建、差分与原生路径测试**：运行 Rust 相关检查、`build`、`diff`；在强制 Rust 后端下执行同一 Python 行为测试，再验证默认路由和回滚行为。支持范围外的输入不得以返回原结果的方式掩盖。
8. **测量收益**：使用批准的主计时器并执行计划中的检查；对相同输入、同等并发和相同构建档位比较，包含桥接、分配、转换及冷/热启动相关成本；规模、资源预算和性能目标在测量前落实。给出输入量 n 的含义、典型与上界负载，检查重复调用、全量加载、复制和无界队列。多核 Rust 对单核 Python 的结果单独标明，不能把并行收益全算成语言收益。性能目标未达成时如实建议保留 Python、扩大计算批次或停止接入。
9. **完成 §7 验收并交接**：获批主工具检查、项目相关检查、可安装产物和证据齐全后才标记该单元完成。不要以纯算法测试代替宿主、服务或发布验收。

某一步未通过时，继续解决该步骤或明确报告阻塞，不把后续未运行项写成通过。
