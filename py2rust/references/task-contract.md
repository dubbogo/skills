# 本包采用的任务契约与证据方法

这里将源 `issue-harness.md` §1.1、§二至§六及 `review.md` 的相关证据方法落实到迁移任务，支持本包单独安装。它不是对当前任务的新授权，也不要求每个本地试点都创建 GitHub Issue。任务明确采用完整 harness 时，依其选定版本与原批准契约执行。

## 需求与权限（对应 harness §1.1、§二、§三）

- 用人话写清问题、目标行为、不变量、非目标及直观成功例子。核实实现入口、直接与间接依赖、历史保护和现有测试，不从待交付实现反推预期。
- 每个迁移单元确定修改所有者、允许/禁止范围、API/数据兼容边界、依赖变化、默认入口接入与否；区别硬依赖、建议顺序和共享文件冲突。
- 验收矩阵是任务的权威判据：风险 → 输入/步骤 → 明确预期 → 环境/真实依赖 → 命令 → 证据。覆盖适用的正常、边界、异常、配置消费、兼容与资源路径，不机械加无关检查。
- 仅请求分析时提供计划；明确授权实施时完成当前范围内本地修改、构建和验证。此前仍有效的授权和工具决策继续使用，不按会话重复确认。
- Issue 发布授权与批准具体任务契约分别记录。限范围定稿授权可以按约定边界定稿，不能自行扩大范围。外部系统写入、GitHub、push、merge、部署等依各自已有授权。
- Issue 开工或恢复时，读取最新正文、原始批准记录和固定获批版本，核对 Theme、范围、依赖、权限及验收。正文写“已批准”不是独立批准依据；不一致时停止依赖该契约的步骤并报告 HOLD。

## 执行模式（对应 harness §四、§五、§6.2）

| 模式 | 开工条件 | 可以声称什么 |
|---|---|---|
| 持续双 Agent | 独立验证者实际核对开工快照并反馈 CONTINUE | 对实际核对的过程检查点及最终快照报告独立结果 |
| FINAL_INDEPENDENT_REVIEW | 开工自检及针对契约/模式的有效人类批准 | 最终独立验证实际完成后报告该结果 |
| SELF_CHECK_ONLY | 开工自检及针对契约/模式的有效人类批准 | 自检结果；独立验证为 NOT_RUN |

仅在任务采用完整 harness 时默认使用其持续双 Agent 模式；其他本地任务遵循用户已授权范围和明确验收要求。宿主缺少所需会话、快照传递或反馈能力时记录 BLOCKED，不能擅自降级。获批模式继续有效。

## 快照与证据（对应 harness §3.2、§3.3、§5.1）

提交态记录仓库身份和精确 SHA。未提交态还需 HEAD、完整 status、staged/unstaged diff、新增文件的路径/模式/内容摘要、submodule、构建与环境输入、契约版本；按确定排序生成快照摘要。影响结果的忽略文件也属于输入。

迁移补充参考实现、语料、比较规则、锁文件、feature、toolchain、解释器、构建档位、原生扩展或 wheel 身份。快照变化后只复验受影响项；未变前提的证据可明确说明后复用。

验证者独立读取契约、源码、测试和产物，不以执行者总结代替证据。交付快照保持只读；运行测试需要写入时重建验证副本，红性探针用另一个一次性副本，不修改交付断言。

`PASS / FAIL / BLOCKED / NOT_RUN` 是执行结果；`N/A` 是带理由的适用性。退出码 0、零用例、skip 或 fallback 不独自构成 PASS。方向判断与正确性分别报告。

关键回归需要可信的原缺陷失败与修复结果、适用 Base/Head 对照，或针对性变异/故障注入；反证失败来自目标行为，断言、选择器与 skip 条件保持不变。无关编译或导入错误不是红性证据。

## 检查点（对应 harness §6.3）

- CONTINUE：当前阶段必需项有证据地通过，方向符合、快照一致、无越权；不表示全部完成或允许合并。
- CORRECT：在原契约内有具体纠偏方案。相同验收项连续两轮正式纠偏仍失败时 HOLD；普通编译/调试失败次数不等于正式轮数。
- HOLD：契约歧义、范围/权限/依赖/验收需改、快照无法确认、必要环境或证据缺失。给出恢复条件；由有权者决定契约变更并固定新版本，重验受影响结论。

## 三层验证循环

- 内层（沙箱）：不依赖外部服务，以秒级反馈为目标，运行比较器负控、目标单测、本单元局部差分（输入/输出检查）和本单元相关的高信号 Rust 检查；失败样本可自由试验。交付前的必需门禁按 gates.md §7 补齐，不受内层秒级目标约束。
- 外层（回放/shadow）：同一构建身份在固定语料或已批准隔离环境复跑，确认差异消失且未引入新差异。
- 记忆层：人工纠正转成三类产物——`DECISIONS.md` 规则、对同类模式的全局排查、永久检查（回归测试、lint、合并检查）。
- 人工门禁设在内层到外层之间：通过内层差分但改变依赖/架构或引入临时绕过（硬编码、复制数据、跳过服务调用）的修复，由人决定能否发布；比较器只判断输出一致，不判断修复可交付。

原始日志按敏感信息政策保存，仅展示必要脱敏片段。不使用生产凭据补足测试条件。不可信代码执行前核验实际隔离，不能将普通 worktree 当作沙箱。引用 CI 时核对实际 checkout、真实命令、选择集与用例，分清关联 SHA 和实际受测 SHA。
