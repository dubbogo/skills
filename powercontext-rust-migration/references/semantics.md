## 8. 差分格式与语义矩阵

每个单元只展开相关项，并写出期望语义及用例依据：

| 类别 | 需要核对的行为 |
| --- | --- |
| 数值 | Python 任意精度整数、bool/int 区别、负数整除和余数、溢出、负零、NaN/Infinity、浮点累加顺序与输出格式 |
| 字符串 | Python 字符索引与 Rust UTF-8 字节偏移；组合字符、casefold 扩展、Unicode 版本、孤立代理项、空白与换行。UTF-16 仅在 JS/JVM/协议边界确实使用它时适用 |
| 正则 | lookaround、反向引用、`\w/\d/\b`、大小写与 Unicode 行为。`regex` 不支持某语法不等于 Rust 生态无法实现；替代库和改写都需要差分验证 |
| 容器 | dict 插入顺序、集合无序契约、重复项、稳定排序与 tie-break、可变对象和别名，以及返回类型 |
| 错误 | 异常类型、错误码、契约要求的文本、参数验证顺序；不能一概转换成通用错误 |
| 时间与随机 | timezone、精度、单调时钟与墙上时钟、deadline 及 ID 之间的关联；优先固定依赖或验证关系约束 |
| 状态与并发 | 事务边界、幂等、取消、超时、重试所有权、资源释放；不能只比较最终输出 |
| 检索与存储 | 词典、分词、编码、序列化、哈希身份、索引版本、历史记录读回和缓存绑定 |

Golden 格式必须无损表达本单元输入输出。标准 JSON 不能可靠承载 bytes、tuple/set、任意大整数、非有限浮点、Decimal、特殊字符串和异常；使用有版本的类型标记或专用编码，并核查编解码回环。不要因为 JSON 序列化失败就丢弃 case。JSONL 按物理 LF 分隔记录，不用会将 U+0085/U+2028/U+2029 等内容字符拆成记录的 `splitlines()`；重复录制前确认合并或覆盖行为，固定最终语料来源与身份。

非确定性按以下顺序处理：固定输入或依赖 → 重置隔离状态 → 对有契约依据的字段进行显式规范化或关系校验。每条规范化记录字段、规则、理由和因此失去的验证能力。工具自动产生的 wildcard、忽略顺序、`...` 或浮点容差必须逐项审查，不能自动接受。

身份、鉴权、错误码、候选顺序、词项和数据库状态等关键语义不得随意通配。不能固定又不能定义有效判据时标为未验证/阻塞，不用通配符宣称完全等价。

环境只记录允许公开的相关变量名、非敏感值、版本及缺失状态；不得保存完整环境快照、token、凭据、私有路径或未经授权的生产内容。
