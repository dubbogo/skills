## 6. 桥接、打包与回滚

| 现有边界 | 优先方案 | 必须核对 |
| --- | --- | --- |
| 同步纯数据变换、批量计算 | PyO3 扩展，Python 保留公开入口 | 参数和返回类型、异常、GIL、线程安全、复制与转换开销 |
| 异步编排中包含同步计算核心 | 编排留在 Python，仅下沉同步核心 | 不阻塞事件循环；已有取消、deadline 和资源归属保持一致 |
| 已独立的 CLI 或协议服务 | 复用该边界评估 Rust 实现 | 参数、退出码、信号、协议、进程生命周期和部署成本 |
| 确实需要新增进程/异步桥 | 单独说明并评审边界设计 | 取消、超时、背压、鉴权、错误传播、幂等、重试和资源上限 |

不能因为用了 `asyncio` 就强制增加进程，也不能把完整 Tokio 服务塞进扩展而忽略生命周期。先找现有可下沉计算边界；新服务边界属于需要明确批准的设计变化。

涉及时间、ID、环境时先检查现有依赖注入和测试夹具。只有契约确有需要时才做最小拆分，不为迁移预建通用端口框架。

对 PyO3 明确：

- 选定扩展名、加载路径和 API 适配位置；同名函数替换不保证 monkeypatch、反射和导入语义天然一致。
- 是否采用 `abi3`、最低 Python 版本，以及对目标 Python 版本/解释器构建的实测支持；不能把 `abi3` 当作免测保证。
- 沿用项目已有 Hatchling 发布约定；若使用 maturin 构建原生组件，说明如何进入 wheel/sdist。不能未经设计直接替换根构建后端。
- 开发机 `maturin develop` 成功后，还需在干净环境安装构建出的 wheel，并通过 Python 的真实公开入口验证；目标是让终端用户按约定安装，不默认要求他们本机编译 Rust。
- 定义 Python/Rust 后端的选择和扩展缺失行为。测试必须可强制 Rust 且禁止回退；生产是否允许回退由已批准方案决定。不得用宽泛 `except Exception` 吞掉 Rust 的运行错误再重跑 Python。
- 回滚代码与数据兼容分开验证：退回 Python 不代表它能读取新格式。涉及持久化变化时，先补齐迁移与恢复方案。

后端选择、环境变量或配置新增时，至少从真实公开入口设置一次非默认值，验证配置最终改变实际运行行为；只检查配置对象或扩展可导入不算链路通过。涉及 FFI、编码或错误映射时，至少覆盖真实成功结果与相关失败/边界结果；两端共享映射时增加不复用该映射的独立期望，避免自洽的错误互相抵消。

涉及生命周期时核对 GIL 释放范围、Python 对象持有、共享缓存、线程/任务退出和成功、失败、取消、超时路径的资源回收。声称重启恢复时，先释放所有实例、连接及 clone，再仅凭持久化介质从真实 open/read/write 入口重建。需要新增诊断信息时遵守项目可观测性规范，不记录请求内容、向量、凭据或敏感路径。
